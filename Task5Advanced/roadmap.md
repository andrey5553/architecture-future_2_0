# Стратегический роадмап внедрения Data Mesh

Компания «Будущее 2.0» \
Горизонт: 3 года \
Цель: \
Создать самообслуживаемую, масштабируемую и доменную систему аналитики, где данные управляются как продукт, а не как побочный эффект.

## Основные бизнес-цели компании (из ТЗ)
| Цель                                                             | Срок                        |
| ---------------------------------------------------------------- | --------------------------- |
| 1. Запуск самообслуживаемой витрины данных                       | Финальное состояние (1 год) |
| 2. Интеграция новых бизнес-направлений без внесения логики в DWH | Долгосрочная (3 года)       |
| 3. Переход от пакетной отчётности к near-real-time аналитике     | Долгосрочная (3 года)       |
| 4. Масштабирование: продукты, география, данные                  | 3 года                      |

## Ключевые роли в Data Mesh
| Роль                     | Обязанности                                                                                                        | Участие в домене                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| Data Product Owner (DPO) | - Владелец "продукта данных"<br>- Определяет SLA, метрики, потребителей<br>- Согласует приоритеты и дорожную карту | Обязательно в каждом домене              |
| Data Engineer            | - Реализует пайплайны<br>- Обеспечивает качество, схемы, мониторинг<br>- Работает с Kafka, Airflow, S3, Iceberg    | В команде домена или платформе           |
| BI-аналитик              | - Использует данные как потребитель<br>- Строит отчёты, дашборды<br>- Формулирует запросы к продуктам данных       | Может быть централизованным или в домене |
| Platform Engineer        | - Развивает общую платформу: DataHub, IaC, CI/CD, мониторинг<br>- Автоматизирует политики                          | В центре компетенций                     |
| Governance Council       | - Определяет стандарты, политики, безопасность<br>- Автоматизирует compliance (GDPR, HIPAA)                        | Над доменами, стратегический уровень     |

## Этапы внедрения Data Mesh

### Этап 1: Подготовка и пилот (0–6 месяцев)
- Цель: Доказать ценность Data Mesh на одном домене.

| Активность                      | Описание                                                                                              | Привязка к бизнес-целям                        |
| ------------------------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Определение пилотного домена    | Выбираем финансовые расчёты (финтех-сервисы) — высокая ценность, чёткие KPI, готовность к инновациям. | Поддержка масштабирования финансовых продуктов |
| Назначение ролей                | Назначаем DPO, Data Engineer, Platform Engineer. Формируем кросс-функциональную команду.              | Внедрение продуктного мышления                 |
| Запуск DataHub                  | Развертываем каталог данных. Добавляем первые "карточки" продуктов: Платежи, Кредиты.                 | Начало самообслуживания данных                 |
| Реализация первого Data Product | Пайплайн: PaymentReceived → Payments Data Product (в S3 + схема + SLA).                               | Переход к near-real-time аналитике             |
| Самообслуживание BI             | BI-аналитик строит отчёт в Power BI, используя данные из каталога, без помощи DWH-инженера.           | Снижение нагрузки на централизованные команды  |

- Результат: Доказано, что аналитики могут работать автономно.
- Время на отчёт: с 2 недель до 2 дней.

### Этап 2: Масштабирование (6–18 месяцев)
- Цель: Распространить Data Mesh на критические домены.

| Активность               | Описание                                                                                        | Привязка к бизнес-целям                   |
| ------------------------ | ----------------------------------------------------------------------------------------------- | ----------------------------------------- |
| Добавление новых доменов | Подключаем: <br>• Пациентский поток<br>• ИИ-сервисы                                             | Поддержка медицинских и финтех-сервисов   |
| Стандартизация платформы | Внедряем:<br>• Единый Schema Registry<br>• IaC для данных (Terraform)<br>• CI/CD для пайплайнов | Готовность к интеграции новых направлений |
| Роли и ответственность   | Каждый домен формирует DPO и Data Engineer. Платформа — централизована.                         | Доменная автономия                        |
| Self-service BI          | Запускаем портал: аналитики ищут данные, смотрят SLA, подключаются напрямую.                    | Самообслуживаемая витрина данных          |
| Near-real-time аналитика | Потоковые пайплайны (Kafka → ClickHouse) для KPI в реальном времени.                            | Переход от batch к streaming              |

- Результат: 5 доменных продуктов данных, самообслуживание в 3 доменах.

### Этап 3: Поддержка и зрелость (18–36 месяцев)
- Цель: Полноценная работа слабосвязанной событийной платформы.

| Активность                                   | Описание                                                                                           | Привязка к бизнес-целям             |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------- |
| Отказ от легаси DWH                          | DWH уходит в режим "архивных отчётов". Новые данные — через события и Data Mesh.                   | Освобождение от техдолга            |
| Глобальные политики через Governance Council | Автоматизируем: <br>• Проверку схем (CI/CD)<br>• Compliance (GDPR)<br>• Управление доступом        | Готовность к выходу на новые рынки  |
| Data Products как API                        | Данные доступны через API с документацией, SLA, версионированием.                                  | Интеграция новых бизнес-направлений |
| Расширение на географию                      | Для нового региона — отдельный проект в облаке, с собственным Data Product для локальных расчётов. | Масштабирование по географии        |
| Монетизация данных                           | Пакеты данных (например, "аналитика по спросу на МРТ") становятся продуктом для фармкомпаний.      | Новые источники дохода              |

- Результат: компания как data-driven организация, где данные — продукт, а не побочный эффект.

## Привязка к бизнес-целям
| Бизнес-цель                                   | Как Data Mesh помогает                                                    |
| --------------------------------------------- | ------------------------------------------------------------------------- |
| Самообслуживаемая витрина данных              | DataHub + Self-service BI → аналитики работают без DWH-инженеров          |
| Интеграция новых направлений без DWH-логики   | Каждый домен управляет своими данными → нет централизованной нагрузки     |
| Переход к near-real-time аналитике            | События + потоковые пайплайны → данные в режиме реального времени         |
| Масштабирование (продукты, география, данные) | Облако + Data Mesh → быстро создаются новые домены с собственными данными |
